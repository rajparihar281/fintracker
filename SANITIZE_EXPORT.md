# Sanitize Export Feature\n\n## Overview\n\nThe Sanitize Export feature allows users to export their financial data while removing or anonymizing personally identifiable information (PII) to ensure privacy-safe data sharing.\n\n## Features\n\n### Export Options\n- **Sanitize Export Toggle**: YES/NO option (defaults to NO)\n- Available in all existing export flows (JSON format)\n- Configurable alongside existing format options (Amount/Type, Debit/Credit)\n\n### PII Handling (When Sanitize = YES)\n\nThe system removes or anonymizes the following information:\n\n#### Account Data\n- **Name**: Replaced with `Account_XXXXXX` (consistent random ID)\n- **Holder Name**: Masked (e.g., \"John Doe\" → \"JXXXXXXe\")\n- **Account Number**: Masked keeping first 2 and last 2 digits (e.g., \"1234567890\" → \"12XXXXXX90\")\n- **UPI ID**: Email masked (e.g., \"john.doe@paytm\" → \"jXXXXXXe@paytm\")\n\n#### Payment Data\n- **Title**: Replaced with `Transaction_XXXXXX`\n- **Description**: Replaced with `Payment description_XXXXXX`\n- **UPI Transaction ID**: Replaced with random `TXNXXXXXXXXX`\n\n#### Category Data\n- **Name**: Replaced with `Category_XXXXXX`\n\n#### Tag Data\n- **Name**: Replaced with `Tag_XXXXXX`\n\n### Data Integrity Rules\n\n**Preserved Data:**\n- Record structure and field names\n- Data types (numbers, dates, etc.)\n- Numerical values (amounts, balances)\n- Statistical and relational data\n- Icons, colors, and UI preferences\n- Account relationships and references\n\n**Consistency:**\n- Same record uses consistent random values across fields\n- Different records get unique random identifiers\n- Multiple exports of same data produce identical sanitized results\n\n## Usage\n\n### In Settings Screen\n1. Navigate to Settings\n2. Tap \"Export\" option\n3. Choose export format (Amount/Type or Debit/Credit)\n4. Check \"Sanitize Export\" checkbox if privacy is needed\n5. Confirm export\n\n### File Naming\n- **Normal export**: `fintracker-backup-[timestamp].json`\n- **Sanitized export**: `fintracker-sanitized-backup-[timestamp].json`\n\n## Technical Implementation\n\n### Core Components\n- `DataSanitizer` class: Handles all sanitization logic\n- Updated `export()` function: Accepts `sanitize` parameter\n- Enhanced export dialog: Includes sanitization toggle\n\n### Security Considerations\n- Sanitization occurs before file generation\n- Original data remains unchanged in database\n- No PII is logged during export process\n- Consistent masking prevents data correlation attacks\n\n## Testing\n\n### Unit Tests\n- PII removal verification\n- Data structure preservation\n- Consistency across multiple calls\n- Edge case handling (empty/null values)\n\n### BDD Tests\n- User interface interactions\n- Export flow with/without sanitization\n- Confirmation dialog variations\n\n### Integration Tests\n- End-to-end export functionality\n- File generation and content verification\n- Performance with large datasets\n\n## Edge Cases Handled\n\n1. **Empty/Null Values**: Gracefully handled without errors\n2. **Short Strings**: Appropriate masking for strings < 3 characters\n3. **Missing Sections**: Export works even if some data sections are empty\n4. **Large Datasets**: Efficient processing of extensive financial records\n\n## Future Enhancements\n\n- Support for additional export formats (CSV, PDF, Excel)\n- Configurable sanitization levels\n- Custom PII field definitions\n- Audit logging for sanitized exports\n- Batch export capabilities\n\n## Compliance\n\nThis feature helps users comply with:\n- Data privacy regulations (GDPR, CCPA)\n- Corporate data sharing policies\n- Personal privacy preferences\n- Third-party integration requirements
